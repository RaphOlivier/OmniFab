# ADR-0024 — Croquis → solide : feature tree event-sourcé, extrusion, topological naming borné (phases B et C)

- **Statut : ACCEPTÉ** — lot ADR-0022..0027 validé par Raphaël Olivier le 2026-10-25.
- **Jalon : 3** — CAO paramétrique + éditeur nodal de valeurs.
- **Source :** préparation du 2026-10-22, digest de session du 2026-10-25 (4 axes tranchés, validation du lot).

**Objet : la première CAO paramétrique réelle — le croquis contraint du jalon 2 devient une feature ; l'historique de construction (feature tree) est le journal lui-même (verrou n°2).**

**Décisions** :
- **D1 — Segments typés `Path2`** (D1 de l'ADR-0016, prérequis jalon 4 CAM) : `Path2` passe de polyligne de points à segments typés `Ligne/Arc/Béziers` + discrétisation pilotée par tolérance (flèche ≤ ~0,01 mm au lieu des segments fixes), chaînage de contours (fermé/ouvert, sens de rotation préservé). Migration douce : l'import SVG/DXF produit désormais des segments typés (arcs natifs), les consommateurs actuels (rendu, export) reçoivent la discrétisation à tolérance — même schéma d'événements, aucun journal cassé.
- **D2 — Le croquis devient de la vraie géométrie** : le pont esquisse→OCCT convertit les entités du croquis (lignes, cercles, arcs) en courbes OCCT natives (GCE_MakeSegment/Circle/Arc), PAS en polylignes discrétisées — l'extrusion produit des faces cylindriques vraies. La fermeture du contour est vérifiée au plan (contour fermé requis pour une extrusion, refus OF-SES-0001 sinon).
- **D3 — Événements feature tree, schémas v1** :
  - `sketch.created { nom, plan }` — multi-croquis nommés (suspens ADR-0018 levé) ; les événements `sketch.entity.added`/`sketch.constraint.added`/`sketch.point.moved` passent en v2 avec champ `croquis` (migration : v1 = croquis d'identifiant 0, le croquis unique historique) ; le champ `plan` n'expose que l'identité XY au jalon 3 (valeur pour les jalons suivants, jamais devinée à la lecture) ;
  - `cad.feature.added { feature }` — v1 polymorphe : `Extrusion { croquis, mode: Addition|Soustraction, profondeur: ValeurCote }` (réutilisation du type `ValeurCote::{Fixe, Expression}` du jalon 2 — une profondeur de feature est liable exactement comme une cote, alias sous préfixe réservé `cad.`) ;
  - `cad.feature.updated { feature }` — à identifiant conservé (patron ADR-0021) : édition du mode ou de la profondeur fixe ;
  - `sketch.entity.removed` / `sketch.constraint.removed` / `cad.feature.removed` — **suppression non cassante** (suspens ADR-0018/0019 levé) : une feature qui référence un croquis supprimé est marquée EN ÉCHEC par la projection (message d'état non destructif, patron D7 ADR-0018), jamais détruite en silence ; suppression d'entité référencée par contrainte : les contraintes tombent AVEC (une commande = un groupe d'undo, patron RemoveAlias).
- **D4 — Le solide est un état DÉRIVÉ, jamais sérialisé** (dans la droite ligne de D3 ADR-0018) : `CadProjection` rechaîne les features dans l'ordre du journal, solide par solide (chaîne OCCT), et produit une tessellation pour le rendu. Moteur CAO **injecté** par l'application (trait `MoteurCad` : reconstruire les courbes du croquis figé, extruder, soustraire, tesseller) — forge-session ne dépend PAS de forge-cad (la LGPL reste confinée ; patron du `Solveur2D` injecté). Cache à clé d'édition monotone, calculs sur le fil de travail, échec d'une feature = message traduit, le reste du rendu survit.
- **D5 — Réédition amont = associativité par le journal** (point 7 du fondateur) : changer une contrainte du croquis ancien, un alias ou une profondeur → le rejeu régénère TOUTE la chaîne aval ; l'ordre du journal = l'ordre du feature tree ; undo/redo par groupes existant suffit (aucun mécanisme nouveau).
- **D6 — Topological naming BORNÉ** (point d'architecture n° 3, le point dur des CAO paramétriques) : au jalon 3, **les références topologiques (faces/arêtes d'un solide aval) restent INTERDITES entre features** — une feature référence un croquis et des paramètres, rien d'autre. En mémoire seulement, chaque face/arête issue d'une feature porte un tag `{feature, index}` pour le survol et la sélection 3D (jamais persisté, jamais référençable par une feature suivante). Le naming complet (identification stable des entités dérivées à travers les rééditions) = design dédié AVANT la première feature qui en a besoin (chanfrein sur une arête du solide → jalon 4) ; toute proposition de référence topologique avant ce design = refus au plan.

**Alternatives rejetées** : sérialiser le solide (double vérité, journal non rejouable — ADR-0001/0018) ; feature tree stocké hors journal (casse l'undo/redo et la reprise) ; recréer le croquis en polylignes (faces cylindriques vraies perdues, récidive D2) ; résolution/solides dans forge-session sans injection (LGPL fuirait, récidive D3 ADR-0018) ; multi-corps au jalon 3 (complexité de naming anticipée pour un gain nul sur le cas d'école).

**Critères de sortie** : croquis rectangulaire contraint → extrusion 4 mm → solide au volume exact (golden) ; poche soustractive au volume exact ; changement d'alias de profondeur → régénération complète (volume recalculé) ; suppression d'une feature → chaîne aval régénérée, undo la restaure ; rejeu ×2 → mêmes volumes (déterminisme) ; le panneau esquisse actuel pilote le croquis sélectionné (multi-croquis UI minimale en phase C).
