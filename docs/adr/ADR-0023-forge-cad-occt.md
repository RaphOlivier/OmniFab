# ADR-0023 — forge-cad : consolidation du noyau OCCT (phase A)

- **Statut : ACCEPTÉ** — lot ADR-0022..0027 validé par Raphaël Olivier le 2026-10-25. **D1 et D8 amendés le 2026-10-28 (checkpoint [J3])** — voir « Amendement du 2026-10-28 » en pied d'ADR.
- **Jalon : 3** — CAO paramétrique + éditeur nodal de valeurs.
- **Source :** préparation du 2026-10-22, digest de session du 2026-10-25 (4 axes tranchés, validation du lot).

**Objet : le jalon de consolidation du fondateur (« bindings OCCT en développement précoce : reprendre un binding existant et le fiabiliser, ou wrapper ciblé via cxx ») — appliquer ADR-0004 : partir d'opencascade-rs, isolé ENTIEREMENT derrière forge-cad, module interne `occt` ; bascule vers un wrapper cxx ciblé seulement si le binding casse/stagne (bornée par cet ADR).**

**Décisions** :
- **D1 — Crate forge-cad, MPL-2.0, OCCT en liaison DYNAMIQUE obligatoire** (LGPL ; exigence du fondateur et du point d'architecture n°5). Vérification d'entrée : `ldd`/`otool`/`dumpbin` en CI de docs (script `docs/occt-dynamique.md`, pas un job) — OCCT n'est JAMAIS vendée dans le dépôt : dépendance système (apt `libocct-*`, brew `opencascade`, vcpkg `opencascade`). Le module interne `occt` est la SEULE frontière : aucun type OCCT dans l'API publique de forge-cad (re-encapsulation, comme le shim planegcs ADR-0013). **→ AMENDÉ le 2026-10-28 : OCCT 7.8.1 builtin épinglée par le lock — voir « Amendement du 2026-10-28 ».**
- **D2 — Périmètre OCCT du jalon 3 (sous-ensemble)** : fondations (TopoDS_Shape, gp_Pnt/Dir), construction filaire→solide (BRepBuilderAPI_MakeWire/Face, BRepPrimAPI_MakePrism), booléens (BRepAlgoAPI_Cut/Fuse), tessellation (BRepMesh_IncrementalMesh + triangules), import/export STEP (STEPCAFControl/STEPControl) et BREP (BRepTools). Toute API en dehors du sous-ensemble = ajout par ADR de lot au fil du jalon (guide d'extension), pas silencieusement.
- **D3 — Golden tests à chaque montée de version OCCT comme d'opencascade-rs** (ADR-0004) : boîte 10×10×5 mm (volume 500 mm³ ± 1e-6), cylindre Ø20×10 (volume), prisme d'un contour croquis (rectangle→extrusion 4 mm), booléen cube−cylindre (volume attendu), STEP exporté → re-importé → mêmes volumes ; les golden tests figent aussi le COMPORTEMENT du binding, pas seulement la géométrie.
- **D4 — Import/export STEP + BREP par forge-cad** (PAS par forge-io : frontière ADR-0009 — forge-io ne dépend jamais d'OCCT). API : `step::importer(octets, budgets) -> Result<Vec<Solide>>`, `step::exporter(&[Solide]) -> octets`, idem `brep::`. Orchestration par commande forge-session (patron ADR-0011 : blob d'octets d'origine, re-parse au rejeu, échec non destructif). .FCStd : **INCLUS en phase A** (décision de Raphaël du 2026-10-25, CONTRE la recommandation suspens) : lecture du conteneur ZIP (Document.xml + fichiers BREP) via le module interne occt, mêmes budgets/patrons de sécurité que STEP, codes OF-CAD-* dédiés ; lecture seule au jalon 3 (aucune écriture .FCStd).
- **D5 — Budgets de ressources aux parseurs STEP/BREP** (patron ADR-0009 sécurité : octets, entités, temps — un STEP de 2 Gio ne gèle pas l'UI), codes **OF-CAD-0001..0004** (échec OCCT générique / shape nul ou invalide / STEP illisible / budget dépassé), registre + tests bidirectionnels ; anyhow interdit, exceptions C++ rattrapées à la frontière du module `occt`.
- **D6 — Unités strictes à la frontière** : OCCT travaille en mm par convention (pas d'unité dans STEP gérée par les en-têtes ; le parseur lit la valeur du contexte STEP et la convertit en mm si nécessaire) ; entrées/sorties forge-units (Length/Angle), jamais de f64 nu dans l'API publique.
- **D7 — Calculs lourds hors fil UI** (patron ADR-0016 C1 : std::thread + mpsc existant) : import STEP, booléens, tessellation ; feature flags native/wasm : forge-cad est `native` au jalon 3 (wasm = jalon 9, sous-ensemble OCCT — l'API publique ne dépend de rien de natif).
- **D8 — CI** : deps natives OCCT ajoutées aux jobs existants (apt/brew/vcpkg) ; **risque documenté : vcpkg opencascade construit OCCT (~30-60 min la première fois)** → cache vcpkg par hash du triplet (actions/cache), sinon le job Windows explose ; si intractable, `continue-on-error` temporaire JAMAIS — plutôt réduire le job Windows à build (déjà couvert) avec cache et documenter le temps. Le mécanisme d'issues CI reste intact. **→ AMENDÉ le 2026-10-28 : plus aucune install OCCT système en CI — voir « Amendement du 2026-10-28 ».**

**Alternatives rejetées** : wrapper cxx d'emblée (ADR-0004 : opencascade-rs d'abord, la bascule est l'exception bornée) ; OCCT statique (LGPL + taille + mises à jour de sécurité — **réévaluée par l'amendement du 2026-10-28**, voir en pied d'ADR) ; forge-io dépendant d'OCCT (casse la frontière ADR-0009) ; parseur STEP maison (délire) ; rust-occ ou occt-rs (moins avancés qu'opencascade-rs à la phase 0 — à réévaluer au spike de la phase A : le spike = compiler un prism depuis un wire, publier le résultat au journal de phase).

**Critères de sortie** : golden tests verts multi-OS ; STEP importé → rendu 3D (wireframe du solide) et exporté (va-et-vient identique aux volumes) ; OCCT vérifiée reproductible sur les 3 OS (builtin depuis l'amendement du 2026-10-28) ; CI verte.

**Risques phase A ajoutés par l'audit n°3 (2026-10-26, `docs/knowledge/archives/2026-10-26-j0-audit3-claude.md`)** :
- **Signatures du binding jamais compilées (B3, retenu)** : les fonctions du module interne `occt` (`Shape::box_with_dimensions`, `Shape::cylinder`, `Solid::extrude_polygon`, `mesh_with_tolerance`, lecture/écriture STEP/BREP) n'ont jamais été compilées (CI rouge depuis `4409a65`, pas de cargo côté assistant). **Vérification du 2026-10-26 (audit n°3, B3)** : les 8 signatures ont été vérifiées contre la source du binding au tag `v0.3` (= 0.3.0 publiée) — toutes présentes et conformes à l'usage ; le risque résiduel est **comportemental** (paniques OCCT à l'exécution sur formes dégénérées/nulles), à trancher par le spike : « phase A livrée » ne se déclare qu'après compilation verte et spike passé.
- **Version `opencascade = 0.3` (B2, réfuté)** : vérifié le 2026-10-26 — la version 0.3.0 existe sur crates.io (publiée 2026-08-24, LGPL-2.1, dépend `glam ^0.24` conforme au projet, `opencascade-sys ^0.3`) ; la génération du lock n'est pas compromise par la version.

## Amendement du 2026-10-28 (checkpoint [J3], commit `d5b4b2c` — validé par Raphaël Olivier)

**Contexte** : OCCT 8.x est sortie (8.0.0 puis 8.0.1 en 2026) et casse opencascade-rs 0.3.0 (épinglage 7.x, issue upstream #237 : `class`→`namespace TopoDS`, pas de fix upstream) ; les gestionnaires système dérivent — vcpkg livre OCCT 8.0.0, brew suit, apt ubuntu-26.04 n'expose plus les paquets 7.x attendus. Le checkpoint [J3] a basculé forge-cad sur **occt-sys 7.8.1 « builtin »** : l'OCCT 7.8.1 est embarquée dans la crate (sources) et compilée par `cargo build`, statiquement, **épinglée par le Cargo.lock** — aucune variance système, reproducible sur les 3 OS.

- **D1 amendé** : l'exigence « liaison dynamique obligatoire, OCCT jamais vendue, dépendance système apt/brew/vcpkg » est remplacée par : **OCCT 7.8.1 builtin via occt-sys, épinglée par le lock** (statique). La LTS jalon est inchangée (gate 7.8/7.9 du binding). Conformité LGPL : l'OCCT reste libre et distribuée sous forme de sources recompilables (registre crates.io + lock) — l'utilisateur peut recompiler l'ensemble ; le script `docs/occt-dynamique.md` et sa vérification `ldd`/`otool`/`dumpbin` deviennent caducs pour forge-cad. La frontière du module interne `occt` est inchangée (aucun type OCCT dans l'API publique).
- **D8 amendé** : plus aucune dépendance OCCT système en CI — retrait des installs apt `libocct-*`, vcpkg `opencascade` et brew `opencascade` (commit `66b3439`, validé par Raphaël) ; les caches vcpkg ne couvrent plus que planegcs (boost/eigen/fmt). Le mécanisme d'issues CI reste intact.
- **Alternative « OCCT statique » réévaluée** : le motif LGPL + taille + mises à jour cède devant le motif dérive 8.x des gestionnaires vs épinglage 7.x du binding — la version OCCT devient un choix du *lock*, pas de la plateforme ; les mises à jour de sécurité OCCT suivent la procédure de veille (fiche veille OCCT, golden tests à chaque montée, jamais en cours de lot).
