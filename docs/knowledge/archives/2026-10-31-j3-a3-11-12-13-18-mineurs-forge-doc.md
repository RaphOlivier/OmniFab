# [J3] Mineurs forge-doc A3-11/12/13/18 — UUIDv7 repris au rechargement, journal corrompu refusé, répertoires ignorés, traversée par segment

**Date :** 2026-10-31 (soir) — **PR :** [#536](https://github.com/RaphOlivier/OmniFab/pull/536) — **Fusion squash :** main `d1d50fce89`

## Contexte (audit n°3, troisième lot des mineurs)

- **A3-11** : le compteur de monotonie des UUIDv7 repartait à zéro au chargement — sous horloge figée, un événement ajouté après rechargement recyclait l'identifiant d'un événement chargé (et forge-session partageait le même txn entre sessions successives).
- **A3-12** : une dernière ligne de journal tronquée était tolérée en silence (warn + break) — or le journal fait foi : un conteneur corrompu doit être refusé.
- **A3-13** : une entrée répertoire `objects/` (zip -r, 7-Zip) était refusée par OF-DOC-0013 (nom vide) au lieu d'être ignorée.
- **A3-18** : `validate_blob_name` refusait tout nom contenant « .. » — `a..b`, nom légitime, était rejeté : la traversée doit se tester par segment.

## Correctifs

- **A3-11** : `nouvel_uuid_v7` ne remet le compteur à zéro que si l'horloge AVANCE (`millis > uuid_derniere_ms`) ; à saturation des 12 bits, la milliseconde de référence avance d'un cran (déterminisme préservé) ; nouvelle `reprendre_compteur_uuid`, appelée en fin de `container::read`, scanne le journal chargé (date en octets 0..6, compteur sur 12 bits des UUIDv7) et repart au-delà du plus grand.
- **A3-12** : la tolérance « dernière ligne tronquée » (`total_lines` + `log::warn!` + `break`) est supprimée — toute ligne non analysable → `CorruptJournal` OF-DOC-0003 ; l'écriture atomique (ADR-0016 A2) et le CRC32 rendaient la tolérance inatteignable pour une vraie troncature.
- **A3-13** : les entrées dont le nom se termine par `/` sont ignorées dans la boucle des blobs (avant `strip_prefix`).
- **A3-18** : `validate_blob_name` teste la traversée par segment — `split('/')` refuse tout segment vide, `.` ou `..` : `a..b` légitime, `a/../b` et `a/./b` refusés.
- **Tests d'intégration** (`tests/document.rs`) : `derniere_ligne_tronquee_toleree` → `derniere_ligne_tronquee_refusee` (OF-DOC-0003 ligne 2) ; `blob_invalide_au_chargement_rejete` sans l'entrée répertoire, + segment `.` ; nouveau test `entree_repertoire_ignoree_au_chargement`.

## Leçons

- Une erreur de résolution (E0599/E0433) masque les assertions qui suivent : un rouge de compilation n'est pas un rouge par assertion — la reprise corrige le test, jamais la lib avant le constat.
- Le premier run d'un correctif peut révéler des tests EXISTANTS qui codifient l'ancien comportement : quand l'audit change la spec, ces tests évoluent avec elle (même PR), sinon ils condamnent le correctif.
- Un SIGABRT glibc (« free(): corrupted unsorted chunks ») après « test result: ok » est un flocon d'infrastructure (heap OpenCascade au teardown), pas un échec de code : vérifier que tous les tests sont passés, puis relancer.
- rustfmt éclate une condition de plus de ~60 caractères en chaînage de méthodes même sous 100 colonnes — écrire d'emblée les conditions longues en chaînage.
- Calibrer les garde-fous sur la base réelle avant de les écrire (`"objects/"` apparaissait 2 fois après édition, pas 1 : le nouveau test + le `strip_prefix` existant).
