# Architecture OmniFab

## Principe directeur

Un **noyau** (workspace de crates Rust) sans aucune dépendance à l'interface ; frontends desktop (egui) et Android (egui, plan B Slint) fins au-dessus. Le web (WASM) est un frontend de plus.

## Crates (briques)

| Crate | Rôle |
|---|---|
| `forge-units` | Newtypes stricts (longueur, angle…) — crate de base, aucune autre crate du noyau ne dépend de moins qu'elle (ADR-0000) |
| `forge-doc` | Conteneur ZIP versionné + event sourcing : journal `events.jl` (JSON Lines, version de schéma par type d'événement, migrations `v_n→v_n+1`, snapshots accélérateurs sans autorité), projection par rejeu (ADR-0000/0001) |
| `forge-values` | Moteur unique de liaisons : graphe de dépendances réactif + expressions, évaluation **paresseux avec marquage dirty** (pull + tri topologique du sous-graphe sale, cycles = erreur typée OF-VAL-0001), expressions déterministes pour le rejeu (ADR-0002) |
| `forge-geom` | Géométrie 2D/3D, NURBS, maillage (parry3d, meshopt, glam) |
| `forge-cad` | CAO paramétrique, contraintes (planegcs via FFI), plans, feature tree |
| `forge-render` | Viewport wgpu |
| `forge-paint` | Raster, calques, filtres, SVG (vello) |
| `forge-cam` | Toolpaths multi-procédés : CNC 3/4/5 axes, fraisage 2,5D puis 3D, tournage, couteau, plasma, laser |
| `forge-gcode` | Générateur, parser, éditeur (colorisation + autocomplétion par dialecte), post-processeurs |
| `forge-link` | Multi-machines en parallèle, transports série + WebSocket, contrôleurs GRBL/FluidNC/Marlin/LinuxCNC, profils maison |
| `forge-io` | Import/export tous formats |
| *(système, pas une crate)* | **Assistants de conception guidée** : templates déclaratifs (données + règles + valeurs normées par secteur) au-dessus de forge-values / forge-cad / forge-cam / forge-io — un assistant est une donnée versionnée, pas du code (matrice §11) |

## Les six verrous (décisions irréversibles, validées)

1. **Format de projet natif : conteneur ZIP** (manifeste JSON versionné + un fichier par objet + blobs binaires), champs version + migration dès le jour 1.
2. **Modèle de document : event sourcing** — chaque opération utilisateur = événement sérialisé rejouable (undo illimité, feature tree, reprise multi-appareils).
3. **Contraintes 2D : planegcs** (solveur de FreeCAD, LGPL) via FFI — pas de solveur maison.
4. **Concurrence : tokio** pour la machine, canaux vers l'UI, géométrie en blocs parallélisés (jamais async). Règle d'or : un freeze de l'UI ne coupe jamais le pilotage machine. *(statut : décision de conception — tokio n'est dans aucun `Cargo.toml` à ce jour, cible des jalons 4/5 sous gel de roadmap ; vérifié 2026-10-26)*
5. **Unités strictes** : newtypes (longueur, angle…), jamais de f64 nu ; tolérance 1e-6 mm.
6. **Liaisons paramétriques : un moteur unique** pour alias et nodal — deux vues du même graphe, zéro incohérence ; s'intègre à l'event sourcing.

## Règles plateformes (cible web non bloquante)

(a) Aucun accès « native only » hors d'un trait d'abstraction avec implémentations par plateforme ; (b) feature flags native/wasm ; (c) deux transports machine dès le départ : série natif + WebSocket (pont local pour le web ; Web Serial API non universelle). OCCT en wasm : sous-ensemble compilé (build complète ~50-70 Mo, cf. opencascade.js).

## Noyau CAO

Bindings OpenCascade (OCCT, LGPL, liaison dynamique obligatoire). **Décision ADR-0004 (2026-10-10)** : partir d'opencascade-rs, isolé entièrement derrière forge-cad (module interne `occt`) ; golden tests de géométrie à chaque montée de version ; bascule bornée vers un wrapper cxx ciblé si le binding casse/stagne.

Frontière : forge-doc = persistance/rejeu bruts, forge-session = intentions métier + undo/redo ; les apps ne touchent plus `Document` directement. Rejetés : événements compensatoires (cassent la compatibilité avant), snapshots autoritaires (ADR-0001), curseur persisté (état caché), commandes dans forge-doc, deux crates session/commands. ## Environnement de développement (2026-10-12)

- **Poste local de Raphaël** : Kubuntu (laptop IdeaPad), Rust **1.99 stable** installé via rustup, clone du dépôt dans `~/OmniFab`. Raphaël **n'est pas développeur confirmé** : cette note ne concerne **que la pédagogie** (commandes exactes à copier-coller, une par une, dans l'ordre ; commits poussés par Vibe via github_app ; explications simples) — **pas le niveau technique exigé**. Les standards restent intégralement appliqués sans compromis : CI stricte (fmt, clippy `-D warnings`, tests, rustdoc), ADR pour chaque décision, six verrous, i18n, codes OF-*. Les décisions d'architecture se prennent à un niveau expert, puis s'expliquent simplement. Raphaël peut aussi coller une sortie `git diff` dans le chat.
- **Suivi CI sans accès Actions** : le connecteur github_app n'expose pas les Actions ; en cas d'échec, `.github/workflows/ci.yml` crée automatiquement une issue « CI : … » avec les logs (120 dernières lignes) — ne jamais modifier ce mécanisme. Depuis le passage public du dépôt, l'API GitHub publique (`api.github.com`, via open_url) permet aussi de lire l'état des runs (attention : limite de débit par IP ; l'absence d'issue « CI : » après un commit est un bon indicateur de succès). Le workflow `android.yml` (ADR-0005) réplique le même mécanisme pour le job `build-apk`. **Leçon du 2026-10-13** : un job peut échouer *avant* l'étape de rapport (échec en ~12 s, `sdkmanager: command not found` — les runners ubuntu-latest n'exposent plus sdkmanager dans le PATH) → aucune issue créée, échec invisible. Correctif `8c80c63` : appel de sdkmanager par chemin absolu `$ANDROID_HOME/cmdline-tools/latest/bin` + repli par `find` + licence automatique. **Toujours vérifier visuellement l'onglet Actions après un changement de workflow**, le mécanisme d'issue ne couvre pas les échecs précoces.
- **Protection de branche `main` : ACTIVE (2026-10-13)** — règle classique, status check requis : « fmt + clippy + tests + rustdoc (Linux) » (nom affiché du job `lint-test` ; le rechercher par `fmt` ou `clippy`, pas par `lint-test`). Leçon : GitHub ne propose dans la recherche que les checks récemment observés — il a fallu pousser une branche temporaire (`ci-checks-registration`, supprimée ensuite) pour rendre le check visible. Pas de « Require PR before merging » (push directs conservés pour l'instant).
- **PoC Android (ADR-0005)** : aucun outil installé en local — l'APK (debug, aarch64) est produit par le job `build-apk` et se télécharge dans l'onglet Actions → artefact `omnifab-android-apk` ; l'installer sur le téléphone demande d'autoriser les « sources inconnues ». Après le push de la crate, Raphaël doit faire `git pull` dans son clone local (Cargo.lock à regénérer).
- **Branches vs pushes directs** : règle actée en conventions v4 (docs → push direct ; code → branche courte + PR sur `lint-test` vert dès retour de la CI) — cf. fiche conventions.
